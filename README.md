# 米家控制台（MiHomePanel）

一个 Windows 桌面端的米家设备控制台。目标是**尽量贴近原版米家 App 的观感**，同时针对桌面
使用场景做取舍：横向空间用来放房间导航和更宽的卡片墙，而不是把手机界面等比放大。

> 非官方项目。通过社区逆向的米家 App 私有接口工作，账号凭据只保存在本机。

> **仍在开发中。** 手里的 56 台设备都是逐台验过的，没见过的品类只能走通用兜底——
> 控件能出、文案可能还是云端英文，欢迎反馈。界面层一直在改，配色和间距不保证稳定。

## 功能

**首页**

- 按**房间分组**的卡片墙，每张卡片是「名称 + 实时状态 + 产品实拍图 + 开关」
- **风扇宽卡（2×1）**：左列「左右扫风 + 角度」，右列「模式 + 风速」。风速会跟着模式
  换成 0–100 的滑条（直吹风）或 1–4 档（自然风）——两个属性在设备里同时存在，
  哪个算数由型号适配说了算。卡片上的这些控件点一下就直接下发，和详情页是同一条
  写入链路（写失败会还原并提示），不需要先点开详情页。**开机时卡片的副标题直接写
  「扫风角度 60 · 风速 45」**，所以第二行不再重复写「角度」「风速」两个名字、滑条右边
  也不再重复写一遍风速，省下的宽度全给轨道（五段角度每段 26 → 33px，风速轨道 67 → 115）；
  拖滑条时数字会临时浮出来给你看，松手就消失。关机时副标题回到「已关闭」，名字和
  数字自己回来
- 卡片样式可改（右键菜单）：小卡 / 宽卡，内容带可选「亮度 + 色温」「亮度」「状态」
  「温度控制」「扫风 + 风速」「实时画面」「极客版入口」；每个品类的默认样式由它自己声明，改一台不影响别人
- **模式、档位、角度这些"互斥几档"的选项是一条轨道**（内嵌分段，选中项实心染色），
  不是一排独立胶囊——扫一眼就知道当前是哪档。区间量（亮度、风速 0–100）用滑条，
  精确小整数（空调温度）用 `− 26 +` 步进器；档位太多（净化器 15 档）会自动退成
  步进器，不会出现"看得见点不到"
- **中枢网关的极客版入口**（宽卡 2×1）：左边产品图，右边一个大按钮。点一下 = 取一次
  **6 位登录码**复制到剪贴板 + 用默认浏览器打开网关的极客版页面，省掉「掏手机 → 进米家
  App → 翻五层菜单」。登录码只能用一次、取新码会让旧的立即失效，所以按钮只在点击时取，
  取码途中不接受连点；离线时按钮点不动。
  点完**按钮上会留下结果**：成功显示「已复制 登录码 + 那 6 位」，失败显示「获取登录码
  失败」，两种情况下面都挂着「重新获取并打开极客版」，回来直接再点一次就行。这行结果
  停 30 秒就自己退回常态——刚回来一眼还认得，久了不该一直顶掉按钮本来的说明。同时屏幕
  上半部会弹一条提示（成功绿色 / 失败红色），**切到浏览器也还在**——那串码就在上面，
  粘贴时不用再切回来找。
  **哪台设备有这个入口由程序自己问出来**：启动后台发一条不耗码的查询，能给出极客版地址
  的才在右键菜单里出现（结果存本地，之后不用再问）。所以中枢网关、带中枢的路由器、
  中控屏都能自动认出来，不需要谁去维护一份型号名单
- 多键面板**聚合成一张卡**，按键照实体开关的样子排：1 路是一整块，2–3 路并排成竖条
  （标签竖排），4 路以上退回胶囊网格
- **「转无线」的按键自动认出来**：米家设置里把某一路设成转无线（继电器常通、留给智能灯
  供电）之后，卡片上那一路画成虚线框 + 无线标记、字变灰，点了只提示一句、不切状态；
  详情页里那一行也置灰。设备和卡片的统计里它不算"开启"，批量关灯也不会碰它。
  不想要这些点不动的键，就在卡片右键「卡片样式」里选**「隐藏转无线」**：只留有线的
  那几路并按键数重排（三键里中键转无线就摆成两键），单开整块转无线则只剩产品图
- 顶部一排**场景快捷**，点一下执行
- 顶部**家庭切换**横向排列，位置可固定、也可自动把激活的排到最左
- 左侧**房间导航**只列当前家庭的房间，房间多时自己滚动；底部是「耗材」「监控」
  「电脑自动化」三个入口（**目前是占位，点了不会有反应**，对应的页面还在规划）
  和一个常驻「设置」
- **排序全可改**：家庭、房间、设备、场景都能拖动，松手即生效
- **隐藏设备**：网关 / 传感器 / 路由子设备可以收进每组末尾的「已隐藏设备」，卡片右键
  即可切换；整组还能再折叠成一行标题，状态记在偏好里。隐藏不影响轮询和控制
- 顶栏**搜索**：按设备名 / 房间 / 品类 / 按键名过滤
- **给小爱发文字指令**：卡片墙上方的横条里打一句话、回车，交给指定音箱执行
  （米家 App 里叫「执行文本指令」）。左侧可切换发哪台音箱——点开是一排产品图 + 名字，
  支持这个能力的设备才出现，离线的压暗点不动；上次选的那台会记住。面板左下角有
  **「静默执行」**开关：关着（默认）音箱照常回话，开着只执行不念结果，状态会记住。
  一次最多 200 字，按米家的字符白名单清洗，被去掉的字符会明说。发送结果（成功 /
  失败原因）在输入框下方轻提示一次
- **只会有一个窗口**：再次双击图标不会开出第二个程序，而是把已经开着的那个叫到前台
  （换一份数据目录可以并行开，见开发文档「单实例」）。已经有实例在跑时，这次启动会
  明确提示「请从托盘菜单选择退出后再重试」，并显示当前的故障注入状态，不会无声退出
- **关窗进托盘**：点关闭按钮不退出，程序留在右下角托盘里继续跟设备状态；单击托盘图标
  回到窗口，右键菜单是**打开主窗口 / 退出**两项。不想这样可以在
  「设置 → 常规 → 关闭面板时」里选「退出程序」。托盘图标不显示的环境
  （远程会话、精简系统）会自动退回"关窗即退出"
- **看不见就少问几句**：窗口在前台时 3 秒刷新一轮，收进托盘 / 最小化后降到 15 秒，
  点开窗口立刻补一轮。省的是米家云端的请求，不是你的体感
- **点完之后盯得更紧**：发过任何指令（开关、滑条、场景、音箱指令）之后的 5 秒里，
  刷新提到 0.5 秒一轮，所以"按了没反应"或者"设备没照做"半秒内就能看出来，不用等下一轮。
  连续操作不累加——窗口是"最后一次操作之后 5 秒"，最多十轮
- **连不上会明说**：轮询连续失败时，卡片墙顶部浮出一条**警告条**，网络、授权失效、
  云端拒绝、返回内容无法解析分开说。它**不自动消失，也不挤动页面**，点 × 才收起；
  这次故障期间不再重复出现。授权失效与限流**第一次失败就提示**，纯网络类连续 3 次
  或持续 8 秒才提示。故障恢复后同一条**原地变绿**，写明连续失败了几次、持续多久，
  同样要手动关。系统通知只是加强通道，本次运行内同一类问题只弹一次

**详情页**

- 主控件在上、只读读数居中、其余可写属性收进「更多功能」；离线时控件整体禁用，
  底部常驻「数据更新于 N 秒前」
- 只读读数**超过 3 天没更新**时，在数值左侧标一行浅灰小字（如「13 个月未更新」），
  和底部那句「刚读到」是两件事
- 枚举项显示**中文短名**：云端的 `Quick Single Click`、`空场景（…）` 转成「单击」
  「空场景」，原文挂在鼠标提示上；故障码（`C1` / `E2.1`）保持原样，报修要用

**设置**

- 外观（主题、家庭标签样式、摄像头通道）、排序、隐藏设备、账号、常规五个分类
- 浅色 / 深色两套主题随时切换；窗口大小、主题、当前家庭都会记住
- 「设置 → 账号」看登录状态、打码后的账号 ID、凭据文件位置，也能**退出登录**
- 「设置 → 常规 → 启动设置」里两项：**开机自启动**写一条 Windows 启动项；
  **启动时最小化到系统托盘**（默认开）让它登录后直接待在托盘里，不在桌面上弹窗口。
  不开第二项就退回"最小化到任务栏"。**第一项只有打包成 exe 后才能用**——源码运行时
  它是灰的，副标题写明原因
- 「设置 → 常规 → 关闭面板时」决定点关闭按钮是**退出程序**还是**最小化到托盘**
  （默认后者）

**摄像头**

- 详情页顶部是**实时画面**：经本机 `go2rtc` 把米家 P2P 码流转成 RTSP，Qt 自己解码渲染
- 进页面只在后台把 `go2rtc` 起好，**点播放键才连**，可随时暂停/继续；支持弹出**独立窗口**
  （独立窗口里画面左下角有一个半透明的云台方向盘，右下角那排暂停/喇叭/收回键照旧）
- 卡片本体也能直接播。**双击进详情时画面跟着走**（不重连），关掉详情页又自动回到卡片上
- **画面带声音**，右下角喇叭键控制开关（**每次开播都是静音**，点一次开；这个选择只对
  这一次观看有效）。只做「有没有声」，没有音量滑杆；摄像头本身没有麦克风时喇叭键不出现
- 局域网不可达时自动回落到远程中继，不用手动切

**界面细节**

- **自绘标题栏**：没有 Windows 原生白条，最小化 / 最大化 / 关闭和拖动、双击、贴边缩放
  都是自己实现的，跟着主题走
- 窗口 12px 圆角（最大化自动切直角）；子窗口比主窗口深/浅一档底色 + 一圈描边 +
  左侧主色窄边，弹出时主窗口整体压暗
- 滚轮只滚页面——**任何情况下都不会顺手把设备参数改掉**

**快捷键**：`Ctrl+F` 搜索、`Esc` 清空当前输入（光标在指令条里就清指令，否则清搜索）、
`F5` / `Ctrl+R` 刷新设备列表、`Ctrl+,` 打开设置。

## 运行

**Windows 直接双击 `run.bat`。** 它会检查虚拟环境和 PySide6，缺什么装什么，然后启动。

```bash
# 等价的手动步骤
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m mihome
```

首次运行会弹二维码，用米家 App 扫码。凭据写在 `~/.config/mijia-api/auth.json`，
和 mijiaAPI 的命令行工具共用，不用重复登录。

依赖只有四个（`requirements.txt`，开发与发布用 Python 3.13）：

| 包 | 版本 | 用途 |
|---|---|---|
| mijiaAPI | >=5.0,<6 | 云端签名、加解密、token 刷新（GPL-3.0，决定了本项目也是 GPL-3.0） |
| PySide6 | >=6.7 | 整个界面 |
| qrcode / pillow | >=7.4 / >=10 | 扫码登录的二维码渲染与图片处理 |

「设置 → 账号」里能**退出登录**：会删掉那个 `auth.json`，然后直接拉起扫码窗口。
米家 App 和云端的登录状态不受影响。目前**同一时间只支持一个账号**，换号就是
「退出登录 → 重新扫码」。

摄像头画面需要额外装一个取流组件（可选，不装只是没有画面），见下文「摄像头」。

## 数据与隐私

全部本地文件都在 `%LOCALAPPDATA%\MiHomePanel\`：

| 路径 | 内容 |
|---|---|
| `prefs.json` | 用户偏好：排序、隐藏设备、卡片样式、主题、摄像头通道等 |
| `cache/spec/` | 设备规格 JSON 缓存（离线时也能画出控件） |
| `cache/icons/` | 产品图缓存 |
| `cache/capabilities.json` | 能力学习账本：确认不支持的属性记下来，之后跳过不再重试 |
| `logs/` | 自检结果、崩溃日志；轮询健康日志 `poll_health.log` 与上次运行快照 `poll_health.last.json`；摄像头取流计时（**默认不写**，见「摄像头 → 已知边界」） |
| `go2rtc/` | 可选取流组件与它的构建记录、许可证 |

登录凭据单独放在 `~/.config/mijia-api/auth.json`（Windows 上是 `C:\Users\<用户名>\.config\mijia-api\`），
由上游 mijiaAPI 管理，**不随安装包分发**，也不在程序目录里。

删掉 `prefs.json` 等于把界面设置恢复默认，不影响登录和设备缓存。

## 摄像头

米家摄像头没有公开的码流地址，走的是私有 P2P，厂商 SDK 有商业授权、不能进本项目
（GPL-3.0）的发行包。所以取流交给可选的独立进程 [go2rtc](https://github.com/AlexxIT/go2rtc)
（MIT），程序只消费 `rtsp://127.0.0.1:<port>/cam_<did>`。

**装一次即可**（约 7.7 MB，走 GitHub assets API 下载）：

```bash
.venv\Scripts\python.exe scripts\install_go2rtc.py    # 官方构建，首帧约 5–6 秒，**没有云台**
.venv\Scripts\python.exe scripts\build_go2rtc.py      # 自己编带补丁的版本，首帧约 2 秒，带云台
```

两个脚本都装到 `%LOCALAPPDATA%\MiHomePanel\go2rtc\go2rtc.exe`，也可以用环境变量
`MIHOME_GO2RTC` 指向别的副本；想回退到官方构建，把留存的 `go2rtc-official.exe` 改名
回 `go2rtc.exe` 即可。没装时画面区会直接写「没有找到 go2rtc」并给出安装命令，不会静默失败。

已知边界：

- 只做**实时画面 + 声音 + 云台方向**。画质切换、SD 卡回放、云存储录像已明确取消
  （理由见 [TODO.md](TODO.md)「摄像头二期」）
- **云台**是画面上的一个圆，上下左右四块：**点一下走一格，按住超过约半秒才开始连转**，
  松手停。详情页里排在画面下方；**独立窗口里是半透明、贴在画面左下角**（常驻，压在
  画面上但能看见底下的内容）。一格转多少由摄像头固件决定（约 15°），程序这边没有更细的
  步长可调。**要求用 `build_go2rtc.py` 装的那份 go2rtc**——官方构建里没有云台接口，
  方向盘整块不出现（不是灰的、不可点，是干脆不显示）。只做方向：预置位、巡航、
  跟随、变焦、拖动画面定位都没做
- **声音**每次开播都从静音开始（点播放不会突然出声），点右下角喇叭开；只控有无，
  没有音量、没有对讲。**这个选择只对这一次观看有效**：暂停/继续、换窗口（详情页 ↔
  独立窗口）会保持，重新点播放或重启程序都回到静音。静音只是关输出，不重建会话，
  点一下就出声，不用重新等 GOP
- 对一台摄像头只开**一条** P2P 会话；设备侧最多允许 **3 路并发**（实测第 4 路被设备
  掐断），所以和米家 App 同看没问题
- **暂停不等于断开**：暂停后设备仍在上行推流，也仍占一个观看位。所以详情页闲置
  3 分钟会自动释放连接，点播放重新取流
- 局域网首帧实测 **4.8–5.2 秒**（等一个完整 GOP），装了开播补丁约 **2 秒**；
  跨网走 relay，首帧通常 **6–10 秒**（异地网络未做真实回归）
- 画面是 2960×1666 HEVC，默认**软件解码**：显存一紧时硬解会让进程直接消失，
  代价约单核 12%。想换回硬解设 `MIHOME_CAMERA_HW_DECODE=1`
- 音频疑似影响流畅度时可以设 `MIHOME_CAMERA_AUDIO=0` **整条音轨不取**（连喇叭键一起
  消失）。这是排障开关，不是静音开关
- 画面一直转圈 / 首帧特别慢时要排查，设 `MIHOME_CAMERA_TIMING=1` 再复现一次：
  `logs/camera_timing.log` 会记下从点播放到首帧上屏的每一步（含网卡、SSID、网段，
  用来判断走的是局域网还是中继）。这个日志**平时不写**，开着时 go2rtc 会以 trace
  级别运行、写得更啰嗦；单文件上限 2 MB，超了自动改名成 `.log.1`，只留一代。
  内容**只在本机、不上传**

## 打包成 exe

```bash
.venv\Scripts\python.exe scripts\build_exe.py
```

产物是 `dist\MiHomePanel\`（约 80 MB / 132 个文件，zip 后约 45 MB），**整个目录一起发**：

```
dist\MiHomePanel\
  MiHomePanel.exe
  _internal\            Qt / Python 运行时（PyInstaller 收集后裁掉了用不到的部分）
  go2rtc\               摄像头取流组件（外部进程，PyInstaller 不会自动带）
  LICENSE  NOTICE.txt   本项目 GPL-3.0 + 第三方组件说明
```

脚本结尾会**在产物上**跑两项检查，都过才算打完：`--self-check`（找得到 go2rtc、
HEVC 解得了）和一次**无控制台启动冒烟**。这两项都不碰摄像头，所以还要手动真播一次：

```
dist\MiHomePanel\MiHomePanel.exe --probe-camera            # 跑一次
dist\MiHomePanel\MiHomePanel.exe --probe-camera --rounds 3 # 冷启动三次看区间
```

`--console` 打带控制台的版本排障，`--onefile` 打单文件（启动慢），`--no-slim` 打完全不裁
的对照版，`--keep-sw-opengl` 保留软件 OpenGL 后备（**发到虚拟机 / 远程桌面时务必加上**）。

打包产物不含任何个人信息：凭据在用户目录，偏好和缓存在首次启动时才生成。

## 目前没做的

完整的待办在 [TODO.md](TODO.md)。近期明确排在后面的是：

- **把电脑接进全屋智能**（下一阶段主线）：电脑事件触发米家场景、米家设备变化反过来
  操作电脑。设计草案与落地顺序都在 TODO 里
- **多账号切换**、**排序页改版**
- **桌面挂件**（复用现有卡片组件）
- 门锁开锁记录、人体触发这类**事件**：接口已经找到了（`/miotspec/event/get`），但**功能还没做**；
  同理，与米家 App 自动化的互通（读自动化列表、发"虚拟事件"触发自动化）也停在调研阶段
- **耗材监控页 / 独立监控页 / 电脑自动化**：左侧功能区的位置已经留出来（三个按钮
  目前只是占位），页面本身还在规划。耗材页的定位是"用户自己添加设备与属性"，
  不做全屋自动识别；电脑自动化是下一阶段主线（把电脑接进全屋智能）的入口
- **局域网直连**（miIO / MIoT LAN）：**明确不做**。虽然能把响应压到几十毫秒，但要按设备型号
  各写一套本地会话，换台设备就失效——装到别人家里大部分设备都会失灵，不划算
- 摄像头**只想做实时画面 + 声音 + 云台方向**，到此为止；画质切换、回放、云存储
  都不在计划内（多路同屏还挂在 [TODO.md](TODO.md) 的低优先级里，家里只有一台能用的
  摄像头，没法验）
- **轮询提速**：常态**不做**。前台 3 秒 / 托盘 15 秒维持不变——设备上报走的是设备自己的
  上行配额，和客户端读属性不是同一配额池，不能互相推论；而且端到端 <1 秒的推送通道
  已经实测存在，轮询只是兜底。唯一的例外是"刚发过指令的那 5 秒"压到 0.5 秒，
  那几秒里确实需要更快地看到设备有没有照做
- **米家云 MQTT 推送**：仓库外的探针已经验证**能通**（55 台设备、端到端 <1 秒），
  但订阅要按设备白名单逐台来、实投 QoS 0，而且**拿不到设备上下线**（`state` 主题零
  消息）。缺口没补上之前不接进主程序

## 开发文档

仓库分成四块，改哪块先看对应目录的模块说明（完整清单在开发文档里）：

```
mihome/core     云端访问、规格解析、状态机、适配规则（无 Qt 依赖）
mihome/ui       全部界面，纯代码自绘，没有 .ui / .qss 文件
scripts         云端探测、离线验证、截图、打包、go2rtc 构建
docs            UI 规范与开发文档
```

架构、数据来源、适配层与枚举文案的设计、UI 约束、摄像头实现细节、打包裁剪依据，
以及一长串实测踩过的坑，都在 **[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)**。
改代码前建议先看那份文档的「交互约定」与「踩坑清单」两节。

想知道"某个功能技术上到底能不能做"（云端有没有这条接口、要不要抓包、局域网行不行），
先看 **[docs/reference/README.md](docs/reference/README.md)**——那是已经调研过的结论索引，
每条都标了状态（已落地 / 待排期 / 明确排除 / 仅参考）和落点。
