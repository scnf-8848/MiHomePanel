# 卡片磨砂玻璃（背景模糊）能不能做、该怎么做

> 2026-11-15 研判。**结论：不做**——不是做不到，是**看不见**；截图 + 模糊那条路
> 另有结构性缺陷。技术分析留作备忘，**不要再排期**（要捡起来先看第 4 节）。

## 1. 现状：卡片本来就是半透明的，缺的只是"可模糊的内容"

- 背景：`theme.Surface` 只有 `solid` / `gradient` 两态，共 24 个预设
  （1 黑白 + 6 纯色 + 17 渐变；2026-11-15 研判时是 13 个，11-17 扩到 24，
  数量已变化，下文结论不变），由 `WindowFrame` 在**顶层窗口**上自绘
  （`chrome.py` 的 `background_brush()`），窗口本身是 `WA_TranslucentBackground`。
- 卡片：`DeviceCard.paintEvent` 用 `theme.card_fill(bg, pal)` 填充圆角矩形，
  `card_alpha` 0.76～0.90（黑白预设 1.0）。因为父链
  （`WallView(QScrollArea)` → `pages` → `body`）都不画底色，
  半透明填充**直接压在窗口自绘的背景上**，透出来的就是那层纯色 / 渐变。
- 全仓库**没有任何 blur / grab 相关实现**（`grep -n "blur\|grab(" mihome` 只命中
  拖拽 ghost 和离屏截图脚本）。所以"现在已经是半透明"是 `card_alpha` 的功劳，
  磨砂从来没真正实现过。

**关键判断**：模糊只对**有高频细节**的背景有意义。而本程序当前只有平滑色块。

## 2. 实测：模糊对纯色 / 渐变几乎恒等

离屏（`QT_QPA_PLATFORM=offscreen`）600×400，取「晨光 · 浅色」渐变
`#F9EDD5 → #DAE6F7`、135°，比较模糊前后逐通道差（跳过 60px 边界，
因为边界本来就会变）：

| 背景 | 模糊方式 | 最大差 | 平均差 |
|---|---|---|---|
| 纯色 `#FBEFD9` | 降采样 1/8 + 升采样 | **0/255** | 0.00 |
| 渐变 | 降采样 1/8 + 升采样 | **1/255** | 0.36 |
| 渐变 | 降采样 1/16 + 升采样 | **2/255** | 0.78 |
| 渐变 | 盒式 r=12 ×3 遍（≈高斯） | **3/255** | 1.73 |
| 有细节的图（模拟照片） | 降采样 1/8 | 186/255 | 22.63 |
| 有细节的图（模拟照片） | 盒式 r=12 ×3 遍 | 178/255 | 23.61 |

**读法**：纯色是**严格恒等**（0/255）；渐变是 1～3/255，且差值集中在渐变两端，
在 8 bit 面板上肉眼不可分。而"照片壁纸"一档是 20+ /255 的量级——
**磨砂的全部价值来自背景里的细节，不是来自模糊算法**。

复现方法（不依赖 Pillow / numpy，`QImage.scaled(..., SmoothTransformation)` 降采样
即最常见的"预模糊"近似，盒式模糊用于对照真高斯）。脚本为一次性实验，未入库。

## 3. 三条路线

### A. 截图 + 模糊（另一个工具试的那条）—— 不可行，效果差是结构性的

1. **拿不到干净的"底层像素"**。卡片往上的父控件都不画底色，真正的背景画在
   顶层窗口；`parent.grab()` 只能得到透明/黑，抓顶层窗口又会把**卡片自己**
   （和相邻卡片、文字）一起抓进去 → 要么递归，要么把文字糊进切片。
2. **逐帧成本不现实**。1600×900 ARGB 抓一次 ≈ 5.8 MB，再模糊几十毫秒；
   滚动、悬停、卡片动画都会触发重绘。
3. **缓存就错位**。缓存下来滚动时切片不跟着走，看着像一张没对上的贴纸。
4. 高 DPI / 缩放变化后像素比要对齐一次，容易差一档。

→ 这条路即使做出来也只能"看起来像"，代价是掉帧与错位，**不要重开**。

### B. 模糊"背景源"，卡片按坐标取切片 —— 唯一推荐形态

不做截屏，只处理背景**源**：

1. 背景是纯色 / 渐变：**直接跳过**（第 2 节已证明是恒等变换）。24 个预设零改动
   （11-17 从 13 扩到 24，数量变了，这条结论不变）。
2. 背景是图片（未来的自选壁纸）：导入或尺寸变化时算**一次**
   `blurred = downscale(1/8) → 升采样`，按 `devicePixelRatioF` 缓存。
3. 卡片 `paintEvent` 里：

   ```
   p.setClipPath(rounded_path(...))                 # 圆角裁切
   p.drawImage(target_rect, blurred, source_rect)   # source_rect 由 mapTo(window) 推
   p.setBrush(card_fill(bg, pal))                   # 原来的半透明色调叠上去
   ```

   滚动 / 动画时 `mapTo(window)` 自然跟着变，切片自动对齐，**不需要重算模糊**。
4. 成本：每张卡一次 blit，无逐帧模糊；模糊只在壁纸 / 窗口尺寸 / DPR 变化时做一次。

要点与坑：

- **半径**：≥ 卡片圆角量级（12～20 px @1x），小了像"脏"不像"磨砂"。
- **色调仍要叠**：只铺模糊片会让白字压不住亮背景。参考文档 251 行已有结论——
  没有模糊时应当把不透明度提高 10～15%，反之有模糊时可略降。
- **坐标原点**：`WindowFrame` 有 `SHADOW_PAD` 外圈留白，卡片坐标要落在**面板矩形**里，
  别直接拿窗口 rect 当基准。
- **图片变换要共用**：壁纸的 cover 缩放 / 居中规则必须只有一份（`Surface` 里），
  `WindowFrame` 和卡片切片都从它取，各算一份必然错位。
- 拖动 ghost / 占位虚线卡不取切片（它们本来就不是"真卡片"）。
- 悬停变亮只动 tint 层，模糊层不动（否则悬停会闪）。

估工：`Surface` 加图片态 + 变换 + 缓存（约 40～60 行）、`DeviceCard.paintEvent`
插入 ~10 行、一条离屏验证（切片对齐 / 滚动后仍对齐 / 13 预设不受影响）。
**前提是壁纸功能本身先有。**

### C. 系统材质（Win11 Mica / Acrylic）—— 不采用

- `DwmSetWindowAttribute(hwnd, DWMWA_SYSTEMBACKDROP_TYPE, ...)`（22H2+）或旧法
  `SetWindowCompositionAttribute(ACCENT_ENABLE_ACRYLICBLURBEHIND)`。
- **只能整窗，不能按卡片**；糊的是**桌面壁纸**，不是程序内容。要让它可见，
  窗口底色得变成半透明色调，等于把这套 13 预设的世界观换掉。
- Win10 没有；DWM 丙烯酸在拖动窗口时有明显的跟随延迟。
- 与本项目"背景由程序自己拥有"的设计相反，**不适配**。

## 4. 结论

**2026-11-15 用户定：不做。** 是"不做"，不是"排期"——以后不要再把它当待办翻出来。

1. 背景只有纯色 / 渐变，实测差值 ≤3/255，做出来看不见；截图方案另有结构性缺陷，
   两条都不成立，所以整条路线关掉。卡片保留现在的 `card_alpha` 半透明
   （层次靠"卡片色从底色派生 + 描边"），不再往 blur / 半透明蒙版上加东西。
2. **万一将来非做不可**（例如先落了「自选图片壁纸」，或卡片背后真的铺了实时画面）：
   只按第 3 节 B 做，**不碰 A**。这里留的是技术备忘，不是重开邀请。
3. 想"卡片更有层次"：画一层 2% 的上浅下深渐变或 1px 内高光，**零性能成本**，
   比磨砂划算得多。
