# 快捷场景 → 桌面快捷方式（2026-11-26 提出并当天落地）

> **状态：已落地**（2026-11-26）。代码在 `core/scene_shortcut.py`，接线在 `app.py` /
> `ui/main_window.py` / `ui/wall.py`，实现说明见 `docs/dev/architecture.md`
> 「桌面快捷方式：点一下 = 执行一个场景」。
> 本文保留评估过程与实测数字；**与最终实现不一致的地方，以第 9 节的拍板结果为准**。

## 结论

- **能做，机制已在本机跑通**（不是推演）：ctypes 直连 COM 建 `.lnk`，写入的
  目标 / 参数 / 工作目录 / 图标读回来与写入完全一致。本机没有 `pywin32` / `comtypes`，
  也不需要装。
- **真正要设计的不是"怎么建 .lnk"，而是"点下去之后谁去发那一个请求"**。本项目是
  单实例 + 单份 `auth.json`，第二个进程自己发请求有机会把登录态写坏（见第 3 节）。
  方案因此定成：**网络调用永远只由 GUI 进程做**，第二个进程只负责把"要执行哪个场景"
  摆到桌上然后退出。
- 工作量约 **550 行**（其中验证脚本约 200 行），v1 不含每场景独立图标。
- 三个判据（点一次就执行、失败要能看见、重复点幂等）全部能满足。

## 1. 需求拆解

| 判据 | 含义 | 影响设计的地方 |
| --- | --- | --- |
| 点一次 = 执行一次 | 双击桌面图标，场景在云端跑 | 快捷方式必须把 `scene_id` 和 `home_id` 都带上（只在家庭内唯一，11-25 场景动作已踩过） |
| 成败要看得见 | 不能点了没反应 | 窗口藏着时用托盘气泡，窗口在时用轻提示 + 状态栏 |
| 幂等 | 连点两下不要执行两遍"莫名其妙"的东西 | 每次点击一个待执行条目，按序消费，不合并、不丢 |
| 不添新依赖 | 绿色版、无安装器 | 不用 pywin32 / comtypes / PowerShell 子进程 |

## 2. 实测：`.lnk` 怎么建（本机跑通）

原型在 `scripts/out/proto_lnk.py`（gitignored，随时可重跑），输出：

```
CoCreateInstance(CLSID_ShellLink)   0x0
SetPath / SetArguments / SetWorkingDirectory / SetDescription / SetIconLocation   全 0x0
QueryInterface(IPersistFile)        0x0
Save                                0x0
读回 GetPath: C:\Windows\SysWOW64\notepad.exe
读回 GetArguments: --scene 123456 --home 10000001
读回 GetWorkingDirectory: C:\Windows\Temp
文件大小 1783 字节
```

要点：

- `CoInitializeEx(STA)` → `CoCreateInstance({00021401-…})` 拿 `IShellLinkW` →
  `SetPath / SetArguments / SetWorkingDirectory / SetDescription / SetIconLocation` →
  `QueryInterface(IPersistFile)` → `Save(path, TRUE)`。vtable 序号写死，注释里标清楚
  （`IShellLinkW` 第 20 是 `SetPath`、`IPersistFile` 第 6 是 `Save`）。
- **不需要管理员**，也不碰注册表：`.lnk` 就是桌面目录里的一个普通文件。
- 桌面路径用 `QStandardPaths.DesktopLocation`（实测 `C:\Users\<用户名>\Desktop`，可写）。
  **不能用 `%USERPROFILE%\Desktop` 拼**：OneDrive 接管桌面后那是旧路径，建出来的图标
  用户看不见。
- 目标 exe 路径由 `IShellLink::SetPath` 单独给，**不要自己加引号**（它保存的是路径本身，
  加了引号会变成带引号的非法路径）；只有"参数串"需要引号，而我们只有数字 id，用不上。

## 3. 为什么第二个进程不能自己发请求（关键约束）

三条代码事实：

1. **单实例守卫已存在**（`core/single_instance.py`）：第二个进程 `acquire()` 失败 →
   `notify_existing()` 广播一条全局注册消息，然后自己退出。**这条消息没有载荷**：
   `PostMessageW(HWND_BROADCAST, msg, 0, 0)`，WPARAM / LPARAM 都是 0。想传 `scene_id`
   必须另开一条旁路（见 4.3）。
2. **`auth.json` 只有一个写者才安全**：上游 `_save_auth_data()` 是

   ```python
   with open(self.auth_data_path, "w") as f:      # 先截断，再写
       json.dump(self.auth_data, f, ...)
   ```

   **非原子写**，而且 `_refresh_token()` 成功后还会轮换 `passToken`。两个进程同时过期、
   同时刷新 → 一方把另一方的登录态覆盖掉，极端情况下要重新扫码登录。**一条桌面捷径
   把用户踢下线，这是不可接受的代价**，所以不做"第二个进程 headless 跑一下"。
3. **每次请求都会先 `_refresh_token()`**（`mijiaAPI` 的 `_request` 第一句），
   而 `run_scene` 还会额外 `_get_home_owner(home_id)` 查一次 uid —— 所以
   **`home_id` 必须存进快捷方式**，不能运行时猜"当前家庭"。

顺带一条产品事实：这个程序本来就是常驻（托盘 + 开机自启 + 3 秒轮询），"已经在跑"
是常态，交接路径是主路径，不是兜底。

## 4. 方案（已按此实现）

### 4.1 快捷方式内容

| 字段 | 打包版（frozen） | 源码运行 |
| --- | --- | --- |
| Target | `…\MiHomePanel.exe` | `…\.venv\Scripts\pythonw.exe` |
| Arguments | `--scene <sid> --home <hid>` | `-m mihome --scene <sid> --home <hid>` |
| WorkingDirectory | exe 所在目录 | 仓库根 |
| IconLocation | `assets/app.ico`（`app_icon` 已能定位） | 同左 |
| Description | `米家控制台 · 执行「<名>」` | 同左 |
| 文件名 | `<场景名>.lnk`（用户定：不加前缀） | 同左 |

- **用 `pythonw.exe` 不用 `python.exe`**：否则源码模式下每次点图标都闪一个黑框。
- 源码模式允许创建，但挪仓库目录 / 重建 venv 之后要重新创建——和 `autostart` 同一个
  已知问题（`autostart.current_exe()` 因此只在 frozen 时返回真）。这一条不弹提示，
  写在 `docs/dev/architecture.md` 的边界里。

### 4.2 三种启动态

| 点击时的状态 | 行为 | 延迟 |
| --- | --- | --- |
| 程序已在跑 | 写待执行条目 → 广播 → 主实例执行 | ~0.2 s |
| 没在跑 | **显式启动**（窗口照常出现）→ 拓扑加载完 → 执行 | 几秒 |
| 正在启动中（互斥量已占、窗口没好） | 写待执行条目 → 广播可能丢 → **启动时补捞**（4.3） | 同上 |

- "没在跑"时**窗口照常出现**（2026-11-26 用户定，推翻本节的初版"进托盘"）：
  用户点的是桌面图标，但"静默跑完"意味着他既不知道程序起来了、也不知道场景跑没跑；
  几秒的黑箱比几秒的窗口更难受。窗口 + 托盘气泡「已执行「回家」」是明确的。
- 启动完**留在托盘继续跑**，不自动退出：符合这个程序的常驻形态，也省得下次再等一遍
  拓扑加载。
- "几秒"这个数字没变（启动本身要重连云端、拉拓扑），变的只是**看不看得见**。

### 4.3 交接通道：待执行文件 + 现有广播

- 目录：`<data>/pending/`（`paths.data_dir()` 下，不进仓库）。
- 文件：`scene-<毫秒时间戳>-<4 位随机>.json`，内容极简：

  ```json
  {"scene_id": "1234567", "home_id": "10000001", "at": 1790000000000}
  ```

- **原子写**：先写 `.tmp` 再 `os.replace()`（和 `rules.json` 同一套做法）。写一半的
  文件绝不能被执行。
- **消费规则**：主实例收到广播 → 扫目录 → 按 `at` 升序逐个执行 → 每个文件执行后删除；
  一次最多取 5 个（防止有人连点出一屏）；**`at` 超过 60 秒的条目直接删掉不执行**
  （程序崩溃前留下的残骸，事后突然执行一次场景比不执行更吓人）。
- **启动时补捞**：程序启动、拓扑加载完成后扫一次同一目录。这条是必需的——广播发出时
  主实例的原生消息过滤器可能还没装上（`acquire()` → 装过滤器之间有窗口期），
  `notify_existing()` 连发 3 次只是降低概率，不能消除。
- 为什么不用 `WM_COPYDATA`：需要目标 `HWND`，而主窗口标题会随家庭 / 设备变
  （`single_instance` 的注释里已经写过这个理由），自建隐藏窗口只为收一条消息，代码更多。

### 4.4 执行与反馈

- 执行**直接复用** `Store.run_scene(scene_id, home_id)`：进 `SerialWorker` 的
  `PRIORITY_CONTROL`、走 `_on_scene_done` 的状态文案、成功后 `_notify_command_done()`
  触发 1 / 2.5 / 4 秒全量回读（11-25 场景动作已定这条路，别另写一份）。
- 反馈通道按窗口可见性选：

  | 窗口状态 | 反馈 |
  | --- | --- |
  | 托盘 / 隐藏 | `tray.show_message("米家控制台", "已执行「<名>」")` |
  | 显示中 | `InlineToast` 轻提示 + 顶栏状态文字 |

  失败时气泡改成「场景执行失败 · <原因>」（`last_error` 原样带出），不要静默。
- 场景名从 `store.scenes_by_home[home]` 里查；查不到（场景刚被删）就显示
  「快捷场景」＋失败原因，不要拿 id 当名字。

### 4.5 入口与簿记

- 落点：**首页场景胶囊的右键菜单**（`SceneBar` 已有「执行场景 / 隐藏场景」）：

  ```
  执行场景
  创建桌面快捷方式
  ─────────
  隐藏场景
  ```

- **不做簿记**（2026-11-26 用户否掉初版的 `prefs.scene_shortcuts`）：快捷方式自己带着
  `scene_id`，再点一次「创建」就是覆盖；桌面文件归用户管，改名 / 挪走 / 删掉都在程序
  视野之外，记一份账必然对不上，还得写自愈。**也不做「删除桌面快捷方式」入口**——
  用户自己在桌面删最快。
- 唯一的代价是**同名不同场景**要另起 `(2)`：建之前读回旧 `.lnk` 的 `--scene`，
  同一个场景就覆盖，不同场景就找下一个空位。没有这一步，两个家庭各有一个「回家」时
  会静默互相覆盖。
- 文件名就是场景名（用户定），非法字符换 `_`、首尾空格与句点去掉、超长截到 60 字、
  空名回落成 `场景<id 后 6 位>`。
- 已隐藏 / 已停用的场景**也允许建快捷方式**：隐藏只是首页那排胶囊不画它（11-24 口径），
  用户可能正是为了不占首页才藏起来却仍想一点就跑。

## 5. 坑与边界

| 情况 | 行为 | 备注 |
| --- | --- | --- |
| 场景被删 | 点击 → 气泡「场景执行失败 · 场景已不存在」 | 云端拒绝；不静默 |
| 场景停用 | 同上，原因照原样带出 | `enable=false` |
| 场景改名 | 快捷方式名不跟着改（v1），点击仍正常 | 靠 `scene_id`，与名字无关 |
| 用户切换了家庭 | 按快捷方式里的 `home_id` 执行，**不改**当前页面 | 改家庭会打断正在看的墙 |
| `auth` 过期 / 未登录 | 程序起来后直接弹登录窗，场景不执行；那条 pending 60 秒后被丢弃 | 不静默——用户看得见"要登录" |
| 勾了"以管理员身份运行" | **不要**。UAC 弹窗 + 不同完整性级别的进程抢同一个 `Local\` 互斥量 → 被当成第二实例挡掉，点了白点 | 写在本文与 dev 文档里，不弹提示 |
| 桌面被 OneDrive 重定向 | 正常工作 | 用 `QStandardPaths` 取路径 |
| 源码模式挪了仓库 / 重建 venv | 快捷方式失效（找不到 pythonw） | 和 `autostart` 同类，重新建一次 |
| 未来多账号 | 快捷方式绑定的是"这份数据目录的登录态" | 换账号后 id 对不上会失败并提示，不会误执行 |
| 连续点 5 次 | 执行 5 次（每次都算一次点击） | 一次最多取 5 个，剩下的下一轮 |
| 桌面图标被用户改名 / 挪走 | 程序不知道也不关心；下次「创建」会在桌面另建一个 | 不记簿记，没有"该删哪个"的问题 |

## 6. 明确不做

| 方案 | 为什么不做 |
| --- | --- |
| 第二个进程自己 headless 执行完就退 | `auth.json` 非原子写 + `passToken` 轮换，可能把用户踢下线（第 3 节） |
| `.lnk` 指向 `.bat` / `.ps1` 包装 | 闪黑框、GBK/UTF-8 编码坑、杀软更容易报；而且给"路径里拼场景名"开了注入口子 |
| 注册 `mihome://scene/<id>` URL 协议 | 要写注册表、要装安装器才合规，用户也不熟；将来有安装器再说 |
| 一个快捷方式跑多个场景 | 那是自动化规则（或米家自己的自动化）该干的事，别让 .lnk 长成配置载体 |
| 给 `.lnk` 设全局热键（`IShellLink::SetHotkey`） | 要 explorer 在场才生效，且和本程序自己的自动化热键抢键位；热键已经有正规入口 |
| v1 就做每场景独立图标 | Qt 能写 `.ico`（`QImageWriter` 支持，实测），但那是第二步；v1 用 `assets/app.ico`（用户 2026-11-26 定） |
| `prefs` 里记一份"哪个场景建过快捷方式" | 用户 2026-11-26 否掉：快捷方式自带 `scene_id`，桌面文件归用户管，记了必然对不上 |
| 「删除桌面快捷方式」入口 | 同上：用户自己在桌面删最快，特意进程序删是多一道手续 |

| --- | --- | --- |

| `app.py` | `--scene/--home` 解析（在单实例之前）、交接分支、启动后入队 | 约 30 行 |

| `ui/wall.py` | 右键菜单一项 + 信号 | 约 15 行 |
| `core/store.py` | `run_scene(on_done=)` + `_on_scene_done` 返回 `(ok, reason)` | 约 15 行 |

估算 550 行、实际约 970 行（含验证）：多出来的主要是 `.lnk` 的 COM 封装写得比原型细
（每个 vtable 号都注释、`_Link` 管自己的 `CoUninitialize` 计数）和 6 组验证。

每场景独立图标留 v2（`<data>/icons/scenes/<sid>.ico`，`QImageWriter` 能直接写 ico）。

## 8. 验收

`scripts/verify_scene_shortcut.py`（52 项，纯逻辑 + 一次真实 `.lnk` 往返 + 一次真广播，
**不碰真实桌面**）：

1. **文件名清洗**：`\ / : * ? " < > |` 换成 `_`；首尾空格与句点去掉；超长截到 60 字；
   空名回落成 `场景<id 后 6 位>`。
2. **参数拼装**：frozen → exe + `--scene … --home …`；源码 → `pythonw.exe` + `-m mihome …`；
   工作目录分别是 exe 目录 / 仓库根（`sys.frozen` 临时置真验打包态）。
3. **`.lnk` 往返**：临时目录建一个，读回 path / arguments / working dir / icon 与写入一致；
   同场景再建是覆盖、异场景另起 ` (2)`；读不存在的文件抛 `OSError`。
4. **待执行队列**：写两个 → 按 `at` 升序取回、文件被删；`at` 超 60 s 的丢弃；超过 5 个只取 5 个；
   写一半的 `.tmp` 不会被取走；写坏的 json 丢掉；`now=` 可控。
5. **参数解析**：`--scene` 缺值 / `--home` 缺值 / 非数字 id 一律拒绝并写
   `logs/shortcut.log`；`--scene` 存在时不得走"普通启动"分支。
6. **交接链路（真广播）**：子进程占住令牌、装好过滤器，父进程落文件 + 广播 → 子进程
   drain 到那一条。这条不打桩——互斥量和全局消息都是内核对象。
7. **接线**：墙面有 `scene_shortcut_requested` 信号、主窗口有广播入口 / 创建入口 / 补捞，
   `app.py` 里广播接的是窗口、第二实例先落文件再广播、场景请求时不进托盘。

真机（用户点一下，我这边验不了）：右键场景 → 创建桌面快捷方式 → 桌面上出现
`<场景名>.lnk` → **程序已在跑**双击 → 气泡「已执行」且窗口不跳出来；**先退出程序**再双击 →
窗口出现、几秒后气泡「已执行」；把场景在手机里删掉再双击 → 气泡报失败原因。

## 9. 拍板结果（2026-11-26，已按此实现）

| 问题 | 用户决定 | 落到代码 |
| --- | --- | --- |
| 文件名前缀 | **就叫场景名**，不加「米家 · 」 | `sanitize_name()` 直接用场景名；同名不同场景才加 ` (2)` |
| 程序没在跑时 | **不静默进托盘**；显式启动（窗口出现）然后执行 | `present_window(window, autostart_requested() and scene_request is None)` |
| 图标 | **v1 用程序图标**，后续再设计 | `app_icon.path()` 写进 `SetIconLocation` |
| 「删除桌面快捷方式」 | **不做**；也不写 `prefs` 簿记 | 菜单只有「创建」；`create()` 覆盖同场景、异场景另起 |

第 4 条的理由（用户原话的意思）：快捷方式只是把信号递进来，程序没有理由记"哪个场景
建过快捷方式"；桌面文件用户自己就能删，专门跑进程序里删是多一道手续。
实现上这也确实更简单——少一个字段、少一套自愈、少一处"文件被外部删了怎么办"。
