- 选哪个记到 `TODO.md`，不要只在聊天里说。

### 违规已推送时的处置顺序

1. 停止继续提交；
2. 判断是否凭据（是 → 立刻换）；
3. 评估暴露面（公开多久、有没有 fork / star 的克隆）；
4. 改当前文件；
5. 决定是否重写历史；
6. 在 `TODO.md` 记一条「已处置 + 时间 + 范围」。

### 工程约定：推送线路不写死（2026-11-17）

这台机器通向 `github.com` 有**三条互不相干的线路，各自都会单独坏**：直连（`api.github.com`
一直 200，但 `github.com:443` 会被断）、Clash Verge 的 `127.0.0.1:7897`（关掉就没端口，
开着也可能是"端口在听、上游全超时"）、WorkBuddy 沙箱给每条命令注入的 env 代理（端口每次
重启都变，见过只对 `github.com` 报 `502` 或超时、其它站点全 200 的实例）。

- [ ] **推送 / 拉取走 `scripts/git_push.py`**：先做一次真正的 `HEAD https://github.com/`
      探测（经代理时先 `CONNECT` 再 TLS，能识破"端口在听、上游是死的"），谁通用谁。
      默认等价 `git push origin main`；其它联网子命令用 `--cmd`，如 `--cmd fetch --tags`。
- [ ] **不要把全局 `http.proxy` 设成空值**：空值在 git 里是"明确不走代理"，优先级高于
      `HTTPS_PROXY`。手动 push 走的是 GitHub Desktop，它靠注入这对 env 把系统代理交给
      自带的 git；设了空值它就退化成直连、30 秒后 `Connection died`。
- [ ] 用 curl 测代理时**大小写都要覆盖**：libcurl 先读小写 `https_proxy`，只写
      `HTTPS_PROXY=x` 会被沙箱注入的小写值顶掉，得到假的 502。

### 工程约定：清理本地 git 凭据前先确认归属（2026-11-09）

Windows 凭据管理器里可能同时躺着几个客户端的 GitHub 令牌，**名字都带 github，但归属不同**：

- **Git Credential Manager**：目标名固定是 `git:<scheme>://<host>`（如 `git:https://github.com`），
  作用域通常是 `gist, repo, workflow`，等于全部仓库读写
- **GitHub Desktop**：目标名是 `<服务> - <endpoint>/<login>`（keytar 的 `<service>/<account>`
  形式，如 `GitHub - https://api.github.com/<login>`），是它自己的登录状态

2026-11-09 就因为「名字里都含 github」把 Desktop 的那条一起删了，Desktop 当场判定
「credentials can no longer be used」→ 自动登出并清空账号记录，需要重新 Sign in 一次。

- [ ] 删除前先确认归属：`cmdkey /list` 看不出创建者，只能靠命名格式区分
- [ ] 清完用 `git -c credential.interactive=false credential fill` 验证：应当报
      `unable to get password`（= 已无缓存，会重新弹登录）
- [ ] 本地删掉凭据**不会**让令牌在 GitHub 侧失效，要作废得去
      Settings → Applications → Authorized OAuth Apps 手动 Revoke

### 工程约定：文案可以按类别，行为必须按型号（2026-11-09）

适配层里有两类东西，**风险等级不同，允许的粒度也不同**，加条目时先分清：

- **行为**（`extra` / `mode_active`）——写错会让设备拒收命令或状态错乱 →
  **一律按型号**，键是 `DeviceNode.model` 的精确串，不许按品类推广
- **文案**（`TextLayer`）——纯显示，认不出就退回云端原文，没有任何 IO →
  **允许按类别**。这是「设备特判一律按型号」的**唯一例外**，理由写在
  `mihome/core/adapters/categories.py` 顶部，别把这个例外扩大到行为字段上

新增一条文案时按这个顺序问：

- [ ] 跨品类都会遇到？→ `enum_text.ENUM_ALIAS`（全局词表）
- [ ] 只有某个品类有？→ `adapters/categories.py`，键是 URN 的 `category` 段
- [ ] 只有某台型号有？→ `adapters/<厂商>.py` 的 `ModelAdapter.text`
- [ ] **属性名一律用 URN 名**（`wash-mode` / `door-state`），不用云端中文 `comment`：
      后者是给开发者的描述，改一个字键就失效且不报错。导入期会拦带中文的键
- [ ] 品类层优先写带属性名的条目（`("door-state", "已上锁(反锁：0；童锁：1)")`），
      裸词只收该品类独有的词——否则别的品类一旦也有这个词，会继承一个未必对的短名
- [ ] 改完跑 `scripts/verify_enum_text.py`；要看真实规格剩多少没映射跑
      `scripts/probe_enums.py`（它现在按品类给分布，能直接看出该落哪一层）

## 工程约定：落盘失败必须留痕（2026-11-21 起，长期执行）

**`except OSError: pass` 是禁止的**，`prefs.py` 里那句"偏好丢了不该影响使用，静默
失败即可"就是 2026-11-21 那场事故的源头：exe 里 `prefs.json` 写不进去，用户改完
设置重启就还原、挂件里加的设备记不住，而程序一个字都没说。

- 写盘（prefs / 凭据 / 日志 / 缓存）失败一律 `core/applog.log("<模块>", ...)`，
  至少带**路径 + 原始异常**。`logs/<模块>.log` 是排障第一现场。
- **启动时探一次能不能写**：`Prefs.probe_writable()` 真建一个小文件再删。写不了就
  在界面上当面说（`app._warn_if_readonly`），别让用户对着"改了等于没改"猜。
- 原子替换（`os.replace`）失败先**兜底直写一次**再报错：杀软 / 索引器 / 同步盘短暂
  占着目标文件时，这是唯一能保住用户刚改那一下的写法。
- 解析失败（坏 JSON）**先改名留档**（`prefs.json.broken-<时间>`）再走默认值，
  绝不直接覆盖——否则"到底存了什么"永远查不清。
- 窗口化的 exe 没有控制台，`qWarning` / `print` 等于丢弃。要么 `applog`，要么
  等于没写（`app.py` 里 `install_qt_handler()` 兜住 Qt 那一半）。
- **诊断不能只落在"可能写不进去的那个目录"**（2026-11-21 补）：`logs/` 和
  `prefs.json` 是邻居，数据目录整体被拒写时两者一起消失——那次就是弹了「设置无法
  保存」而 `logs/prefs.log` 一条失败记录都没有。凡是解释"写盘失败"的现场，必须
  另有 `%TEMP%` 兜底（`core/diag.py`，由 `app._report_startup` / `_report_runtime`
  调用），并带上**进程身份**（完整性级别 / AppContainer / 是否提权）——只写路径和
  异常，分不清是权限、沙箱还是安全软件。

## 工程约定：长期约定按模块分层（2026-11-13 起，长期执行）

助手侧的"项目长期约定"原来是一份 `MEMORY.md`（本地 `.workbuddy/`，不入库），一路写到
14 KB，**每次会话注入时都被截断**——被截掉的那几节等于不存在。现在按模块拆开：

- `MEMORY.md` 只放**跨模块**的规矩（文档三分、许可与提交、工具链、通用红线）+ **一张索引表**；
- 各模块的硬约定在 `modules/<模块>.md`：camera / ui-shell / cards / adapters / polling /
